很多站点的配色是"看着舒服就用了"，缺乏体系。这里分享一个以 **魔方六色** 为起点的设计系统搭建思路 —— 它既有个性（与个人 IP 呼应），又足够规范。

## 1. 先定语义，而不是先定颜色

直接使用"红黄蓝绿"会非常混乱。正确顺序是：先列出**语义角色**，再把六色分配进去：

- 主色（强调）：橙 `#EA580C` → 按钮、链接、关键状态
- 中性色：白 `#F8FAFC` → 背景、卡片
- 语义色：绿 → 成功 / 红 → 危险 / 蓝 → 信息 / 黄 → 警告

这样整站颜色与魔方六色一一对应，主题统一且自洽。

## 2. 用 CSS Variables 承载

```css
:root {
  --color-accent: #C2410C;
  --color-accent-hover: #9A3412;
  --color-success: #15803D;
  --color-warning: #B45309;
  --color-error: #B91C1C;
  --cube-yellow: #FACC15;
  /* ... */
}
```

变量名的价值在于**语义化**：组件里永远写 `var(--color-accent)`，换主题时只改 token 文件，全局生效。

## 3. 对比度校验（WCAG AA）

设计系统必须过对比度这关，尤其小字号正文：

- `#52525B` on `#F5F5F4` → 7.4:1 ✅
- `#9A3412` on `#FFEDD5` → 6.6:1 ✅
- 白字 on 主色 `#C2410C` → 5.9:1 ✅

> 设计系统里，每个 token 都应该标注"用于什么场景、对比度多少"，而不是只有色值。

## 4. 六色的另一种用法：装饰与标识

除了语义色，六色还可以作为**纯装饰标识**使用（如模块图标、像素字、魔方装饰）。这类颜色不承担信息传递，自由度更高 —— 但也要控制在"同一屏不超过六种"，保持克制的秩序感。

## 小结

> 一套好的配色系统 = 语义角色 × 变量承载 × 对比度校验 × 克制的使用场景。魔方六色给了它一个有趣的外壳，而规范让它在每个页面上都站得住。
